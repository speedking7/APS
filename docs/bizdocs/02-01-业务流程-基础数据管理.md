## 02-01 业务流程清单 – 基础数据管理域

> **范围**：预测、BOM、物料参数、稼动天数、盘点数的导入、维护与校验。  
> **说明**：每个流程用 `MD-FLOW-xxx` 编码，角色遵循 RASIC（R=Responsible, A=Accountable, S=Support, I=Informed, C=Consulted）。

---

### MD-FLOW-001 完成品入库需求数导入与维护

- **目标**：确保 APS 系统中完成品月度入库需求数据完整准确，为后续 BOM 展开和生产计划计算提供唯一输入源。
- **涉及角色**：需求规划工程师（R）、计划主管（A）、物流部（I）
- **前置条件**：销售部已生成月度完成品需求数据；APS 系统已初始化
- **后置结果**：APS 中存储完整的完成品入库需求数据库，可供生产计划计算使用
- **标准流程**：
  1. **收集需求数据（需求规划工程师）**
     - 从销售系统或需求计划系统导出完成品月度数据，包含：客户、存货编码、年月（YYYYMM）、需求数量、期末库存、最小安全库存；
     - 计算 `完成品入库需求数` = 需求数量 + 最小安全库存 - 期末库存（或由需求计划系统直接输出）；
     - 需求仅适用于完成品级别，子件需求由 BOM 展开推导。
  2. **准备导入文件（需求规划工程师）**
     - 将需求数据整理成 `APS_demand.xlsx`，Sheet 名：`完成品入库需求数`；
     - 必填列：客户、存货编码、年月（YYYYMM）、需求数量、期末库存、最小安全库存、完成品入库需求数、版本号；
     - 版本号建议以日期或迭代编号命名（如 `2026050101`），同一批次数据使用相同版本号。
  3. **批量导入需求数据（需求规划工程师）**
     - 在 APS 系统中调用 `POST /api/excel/import` 接口，上传 `APS_demand.xlsx`；
     - 系统按 **版本号 + 客户** 全删全导：先删除相同版本号+客户组合的全部旧数据，再写入新数据；
     - 系统自动校验数据完整性（存货编码存在、年月格式正确、数量为非负数）；
     - 若校验通过，批量保存；若失败，返回错误信息，工程师修正后重新导入。
  4. **单条新增/修改/删除（需求规划工程师）**
     - 对于需要单笔调整的需求，可在需求查询界面单条操作：新增、修改数量、删除记录。
  5. **需求查询与确认（计划主管）**
     - 计划主管登录系统查询需求数据，按存货编码、客户和年月查看；
     - 重点确认 `完成品入库需求数` 列数据正确，该列为计划计算的实际依据；
     - 确认无误后，冻结版本（标记为"生效"状态）。
  6. **生产计划员取用需求（生产计划员）**
     - 生产计划员触发生产计划计算时，系统自动引用已生效版本的 `完成品入库需求数` 列数据。
- **关键业务约束**：
  - 计划计算以 `完成品入库需求数` 为准，该字段已内含完成品安全库存逻辑（期末库存 + 最小安全库存），不再另行设置完成品安全库存参数；
  - 子件需求严格通过 BOM 展开逻辑推导，不允许手工维护子件需求；
  - 导入规则为按版本号+客户全删全导，同一版本号+客户组合的历史数据会被完整替换，建议定期备份；
  - 计划主管冻结后，需求规划工程师仍可修改，但需要主管再次确认生效。

### MD-FLOW-002 BOM 主数据维护

- **目标**：建立并维护完整的多层 BOM（物料清单）结构，确保生产计划计算和产能人时测算的精准性。
- **涉及角色**：工艺工程师（R）、生产计划主管（A）、物料工程师（S）
- **前置条件**：产品设计已完成，产品 BOM 架构已定义；工序流程已确定
- **后置结果**：APS 中存储完整的多层 BOM 库，可供计划计算和能力规划使用
- **标准流程**：
  1. **收集工艺 BOM 数据（工艺工程师）**
     - 从工艺系统或工艺档案中提取每个产品的完整 BOM 结构；
     - 每行 BOM 记录包含：父零件编码、子零件编码、用量、工序名称、设备编码、模腔数/取数（pcs）、制造周期（S）、持台人数（人）、单件节拍（S）、**报废率**、**版本号**；
     - 报废率代表该制造工步的报废率（0~1 小数），由工艺工程师在 BOM 维护时一并录入，不再使用独立的报废率表；
     - 对于多工序产品，按工序顺序排列各子件消耗信息。
  2. **准备 BOM 导入文件（工艺工程师）**
     - 将 BOM 数据整理成 `APS_bom.xlsx`，Sheet 名：`BOM`；
     - 必填列：父零件、子零件、用量、工序、设备、模腔数/取数（pcs）、制造周期（S）、持台人数（人）、单件节拍（S）、报废率、版本号；
     - 验证数据：父零件与子零件编码在系统中存在、用量为正数、工序和设备编码有效；
     - 制造周期和单件节拍采用秒为单位，便于后续设备负荷计算。
  3. **批量导入 BOM 数据（工艺工程师）**
     - 在 APS 系统中调用 `POST /api/excel/import` 接口，上传 `APS_bom.xlsx`；
     - 系统按 **版本号** 全删全导：先删除相同版本号的全部旧 BOM 数据，再写入新数据；
     - 系统自动校验父子零件关系、字段完整性和数据类型；
     - 校验通过则保存，失败则返回错误清单，工艺工程师修正后重新导入。
  4. **BOM 多层展开校验（生产计划主管）**
     - 在系统中执行"BOM 多层展开预览"功能，检查 BOM 结构的正确性；
     - 验证：完成品 → 半成品 → 原材料的展开路径无循环、无断链、叶子节点为可采购物料；
     - 若发现问题（如循环依赖、缺失子件），通知工艺工程师修正。
  5. **单条新增/修改/删除（工艺工程师）**
     - 对于新增工序或临时工艺变更，可在 BOM 查询界面单条操作：新增 BOM 行、修改参数（用量/工序/设备等）、删除行；
     - 修改后自动重新计算多层展开，供下次计划计算使用。
  6. **BOM 版本管理（生产计划主管）**
     - 定期（如产品设计变更时）冻结当前 BOM 版本，标记生效日期；
     - 新 BOM 版本与生效日期关联，计划计算时按生效日期自动选择相应版本。
- **关键业务约束**：
  - BOM 每行记录代表一道工序，同一子件多个工序消耗需分行记录；
  - 报废率为每制造工步独立字段，不同工序可设置不同报废率；报废率必须基于真实生产数据，不允许凭估计设置；
  - 制造周期和单件节拍的单位必须统一为秒，不允许混用分钟或小时；
  - 模腔数/取数字段用于设备产能计算，必须与实际生产工艺一致；
  - 导入规则为按版本号全删全导，同一版本号的 BOM 数据会被完整替换；工艺变更时建议使用新版本号，保留历史版本可追溯；
  - 工艺变更时，需同时更新 BOM（含报废率）和相关物料参数，确保后续计划精准。

### MD-FLOW-003 物料参数维护（半成品安全库存）

- **目标**：维护半成品的安全库存天数参数，为生产计划计算提供半成品库存下限约束。
- **涉及角色**：库存管理员（R）、计划主管（A）
- **前置条件**：所有半成品物料编码已在系统中注册
- **后置结果**：APS 中存储完整的半成品安全库存参数，供计划计算使用
- **说明**：
  - 本流程**仅维护半成品安全库存**；
  - **报废率已并入 BOM 维护**（MD-FLOW-002），由工艺工程师在 BOM 中按工步录入，本流程不再涉及报废率；
  - **完成品安全库存**在需求表（`APS_demand.xlsx` 的 `最小安全库存` 列）中维护，不在本流程中处理。
- **标准流程**：
  1. **确定半成品安全库存参数（库存管理员）**
     - 根据库存管理政策和物流规划，确定各半成品的安全库存天数（防止缺货的最少库存天数）；
     - 同时确定 `每日当量`（用于将天数换算为实物量）、最大库存天数（防止积压）；
     - 可参考物料供应周期、需求波动性，一般安全天数设置 3~15 天。
  2. **准备导入文件（库存管理员）**
     - 将半成品安全库存数据整理成 `APS_safetystock.xlsx`，Sheet 名：`半成品安全库存`；
     - 必填列：存货编码、每日当量、安全天数、最大天数、版本号；
     - 版本号建议以日期或迭代编号命名，同一批次数据使用相同版本号。
  3. **批量导入安全库存参数（库存管理员）**
     - 在 APS 系统中调用 `POST /api/excel/import` 接口，上传 `APS_safetystock.xlsx`；
     - 系统按 **版本号** 全删全导：先删除相同版本号的全部旧数据，再写入新数据；
     - 系统校验存货编码有效、数值为正数；校验通过则保存，失败则返回错误信息。
  4. **单条新增/修改（库存管理员）**
     - 对于个别半成品参数调整，可在安全库存查询界面单条操作：新增、修改安全天数/每日当量/最大天数。
  5. **参数生效与冻结（计划主管）**
     - 计划主管查看参数维护历史，确认参数无误后冻结版本；
     - 冻结后的版本在规定期间内生效，供后续计划计算调用。
- **关键业务约束**：
  - 本表仅维护半成品，完成品安全库存参数在需求表中维护，两者不能混用；
  - 安全天数变更可能导致计划数量大幅变化，需提前沟通生产和成本团队；
  - 对于供应周期长的半成品，安全库存天数应设置较高（如 20~30 天）；供应稳定的可设置较低（如 5~10 天）；
  - `每日当量` 字段须与实际生产节拍一致，确保天数换算准确。

### MD-FLOW-004 稼动天数维护

- **目标**：维护每月工作日历明细，用于生产计划计算中的需求日均转换和设备可用时间计算。
- **涉及角色**：生产计划主管（R）、生产部长（C）
- **前置条件**：工厂全年节假日、停产计划已确定
- **后置结果**：APS 中存储各月工作日历，计划计算时自动调用
- **标准流程**：
  1. **确定年度工作日历（生产部长）**
     - 综合考虑国家法定节假日、双休日、工厂自定义停产日（如维保、换季），确定每月的出勤天数明细；
     - 需明确：总出勤天数、其中工作日（非周末非节假日）、双休日、国定节假日各为多少天；
     - 一般工厂月工作日为 20~22 天（考虑周六日和节假日）。
  2. **准备导入文件（生产计划主管）**
     - 将工作日历整理成 `APS_workingdays.xlsx`，Sheet 名：`稼动天数`；
     - 必填列：年月（YYYYMM）、总出勤天数、工作日、双休日、国定节假日；
     - 四个天数字段之间关系：总出勤天数 = 工作日 + 双休日 + 国定节假日（可根据实际情况调整）。
  3. **批量导入稼动天数（生产计划主管）**
     - 在 APS 系统中调用 `POST /api/excel/import` 接口，上传 `APS_workingdays.xlsx`；
     - 系统按 **年月** 新增或更新（upsert）：已有该年月记录则更新，无则新增，不清空其他期间数据；
     - 可批量导入年度日历，也可逐月更新。
  4. **稼动天数确认（生产计划主管）**
     - 与生产部确认工作日历数据，确保与实际生产安排一致；
     - 特殊情况（如临时停产、缩短生产周期）需及时更新对应月份。
  5. **生产计划计算调用（系统自动）**
     - 计划计算时，系统自动查询该月的 `工作日` 字段；
     - 用于计算日均需求：日均需求 = 月度需求 / 工作日；
     - 设备可用时间：可用时间（小时）= 工作日 × 10.5 小时/天。
- **关键业务约束**：
  - 计划计算使用 `工作日` 字段（非总出勤天数），确保该字段正确排除双休日和国定节假日；
  - 工作日必须为正整数，通常范围 18~23 天；
  - 若中途发生非计划停产（如设备故障、安全事故），需及时更新该月工作日，并同时调整已生成的计划；
  - 不同工厂/车间可能有不同稼动日历，APS 需支持按工厂或工序维度配置（如需）。

### MD-FLOW-005 半成品期末盘点数导入与维护

- **目标**：导入半成品期末库存盘点数据，作为下一期生产计划计算的期初库存，确保半成品库存约束的准确性。
- **涉及角色**：库存管理员（R）、计划主管（A）、财务（I）
- **前置条件**：月末实物盘点已完成；财务库存结账已确认
- **后置结果**：APS 中存储各期半成品期末盘点数据，用于后续计划递推
- **说明**：
  - 本流程**仅维护半成品期末库存**；
  - **完成品期末库存**在需求表（`APS_demand.xlsx` 的 `期末库存` 列）中维护，不在本流程中处理。
- **标准流程**：
  1. **获取半成品实物盘点数据（库存管理员）**
     - 从 WMS 或库存系统导出月末半成品盘点结果；
     - 数据包含：存货编码、年月（底）（YYYYMM）、可用量（已扣除待检、不良品等不可用库存）。
  2. **准备导入文件（库存管理员）**
     - 将盘点数据整理成 `APS_inventory.xlsx`，Sheet 名：`半成品期末盘点数`；
     - 必填列：存货编码、年月（底）（YYYYMM）、可用量、版本号；
     - 版本号建议以日期或迭代编号命名，同一批次数据使用相同版本号。
  3. **批量导入盘点数（库存管理员）**
     - 在 APS 系统中调用 `POST /api/excel/import` 接口，上传 `APS_inventory.xlsx`；
     - 系统按 **版本号** 全删全导：先删除相同版本号的全部旧盘点数据，再写入新数据；
     - 系统校验存货编码有效、数量为非负数、年月格式正确；
     - 校验通过则保存，供下期计划计算使用。
  4. **单条新增/修改/删除（库存管理员）**
     - 对于盘点后发现的少量调整（如新发现的库存或报废），可在盘点查询界面单条操作。
  5. **盘点数确认与冻结（计划主管）**
     - 计划主管与财务确认半成品盘点数与财务库存结账一致；
     - 确认后冻结该月盘点数，标记为"已生效"，供计划计算调用。
- **关键业务约束**：
  - 本表仅维护半成品，完成品期末库存在需求表中维护，两者不能混用；
  - 盘点数必须与财务库存结账数据一致，否则生成的计划会与财务报表产生偏差；
  - 盘点数是分期库存递推的启动条件，必须完整（不允许有缺失的半成品物料或期间）；
  - 若发现盘点数与实际严重偏离（差异 > 5%），需立即调查原因（盘点错误、中途损耗、未记录的出入库）并纠正。
