## 02-02 业务流程清单 – 生产计划计算域

> **范围**：月度生产计划的自动计算、结果审核、人工调整、多版本管理。  
> **说明**：每个流程用 `PP-FLOW-xxx` 编码，角色遵循 RASIC（R=Responsible, A=Accountable, S=Support, I=Informed, C=Consulted）。

---

### PP-FLOW-001 月度生产计划计算

- **目标**：基于完成品入库需求数、BOM、半成品安全库存和盘点数据，自动按月逐层展开 BOM，计算每个自制件（完成品/半成品）每月的计划生产数量。
- **涉及角色**：生产计划员（R）、计划主管（A）、生产部长（C）、财务（I）
- **前置条件**：完成品入库需求数、BOM、半成品安全库存、稼动天数、半成品期末盘点数等基础数据已按版本号导入并确认
- **后置结果**：生成完整的生产计划结果集，包含每个自制件每月的需求数、计划生产数，以及 BOM 中的工序/设备/节拍等信息，供能力测算使用

---

#### 核心计算逻辑

##### 1. 整体流程

1. 用户指定版本号，触发计算；系统根据版本号读取对应的所有基础数据。
2. **按月份逐月计算**（不可跨月合并）。
3. 每月内：先遍历完成品入库需求数，再通过 BOM 向下展开，逐层推导半成品计划生产数。

##### 2. 完成品层（第 1 层）

- **输入**：完成品入库需求数（已包含安全库存和期末库存的调整，无需再单独扣减）。
- **计划生产数公式**：

  ```
  完成品计划生产数 = 完成品入库需求数 ÷ (1 - 报废率)
  ```

- 完成品不单独处理期末库存和安全库存（已体现在入库需求数中）。
- BOM 中同一完成品若有多道工序（多个 BOM 行），每行均记录该完成品的计划生产数及对应的工序/设备/节拍信息。

##### 3. 半成品层（第 2 层及以下）

对于 BOM 中每一个子件（半成品），按以下步骤计算：

**Step 1：计算毛需求**

```
半成品毛需求 = 上层件计划生产数 × BOM 用量
```

**Step 2：扣减现存量（期初库存）**

- **第一个月**：从"半成品期末盘点数"表中查找该物料的可用量作为现存量。
- **后续月份**：现存量 = 上个月的期末库存（由上月计算结果递推而得）。

> **同月多次使用时的消耗规则**：若同一半成品在同一月内出现于多个完成品的 BOM 中，其现存量须**逐步消耗**，不可每次都用相同的初始值：
> ```
> 本次可用现存量 = 上次计算后的剩余现存量
> 剩余现存量 = max(0, 上次可用现存量 - 本次毛需求)
> ```

**Step 3：加安全库存**

```
净需求 = 毛需求 - 当前现存量 + 安全库存
```

- 安全库存：按**物料编码 + 年月**从"半成品安全库存"表查找。
- **同月多次出现时**：安全库存**只在当月第一次计算该半成品时加一次**，后续出现不重复叠加，避免安全库存虚高。

**Step 4：判断是否需要生产**

```
净需求 ≤ 0  →  计划生产数 = 0，不再向下展开该半成品的下级件
净需求 > 0  →  继续 Step 5
```

**Step 5：计算计划生产数**

```
半成品计划生产数 = 净需求 ÷ (1 - 报废率)
```

**Step 6：继续向下展开**

以该半成品的计划生产数为输入，对其所有子件重复 Step 1~5，直至整棵 BOM 全部展开完毕。

##### 4. 期末库存递推

每月计算完成后，每个半成品的期末库存供下月使用：

```
期末库存 = max(0, 现存量 - 毛需求) + 计划生产数 × (1 - 报废率)
```

（若净需求 ≤ 0，则计划生产数 = 0，期末库存 = 剩余现存量）

##### 5. 版本管理

- 每次计算必须指定版本号（各基础数据表各自对应的版本）。
- 计算结果保存时附带版本号，支持多版本共存和对比。

---

#### 结果集字段

| 字段 | 说明 |
|------|------|
| 工序 | BOM 中对应的工序名称 |
| 设备 | BOM 中对应的设备编码 |
| 自制件 | 当前层的物料编码（完成品或半成品） |
| 完成品 | 该自制件所属的顶层完成品编码 |
| 需求 | 净需求（扣减库存、加安全库存后） |
| 生产 | 计划生产数 |
| 年月 | 计划月份（YYYYMM） |
| 模腔数/取数(pcs) | BOM 字段 |
| 制造周期(S) | BOM 字段 |
| 持台人数(人) | BOM 字段，供人员需求测算使用 |
| 单件节拍(S) | BOM 字段，供设备负荷测算使用 |
| 报废率 | BOM 字段 |
| 版本号 | 本次计算使用的版本标识 |

---

#### 标准操作流程

1. **检查基础数据完整性（生产计划员）**
   - 确认完成品入库需求数、BOM、半成品安全库存、稼动天数、盘点数已按版本号完整导入。
   - 重点检查：BOM 无断链；盘点数覆盖计划起始月的前一个月；安全库存按年月配置齐全。
2. **触发生产计划计算（生产计划员）**
   - 进入"生产计划计算"功能，选择计划起止月份及各基础数据版本号，点击"开始计算"。
3. **系统执行 BOM 展开与计划计算（系统自动）**
   - 按上述核心计算逻辑，逐月、逐层递推，写入结果集。
4. **审核计划结果（生产计划员 / 计划主管）**
   - 检查计划数量合理性，对比上版本差异，确认无误后冻结版本。
5. **导出与发布（生产计划员）**
   - 冻结版本后导出为 Excel，分发至采购、生产排程、能力规划等下游团队。

---

#### 关键业务约束

- 报废率以小数形式存储（如 3% = 0.03），公式中直接使用，填写错误将导致计划严重偏差。
- 同月同半成品的现存量必须逐步消耗，不得重复使用初始值。
- 安全库存每个半成品每月只叠加一次，避免多完成品共用同一半成品时安全库存虚高。
- 计划起始月必须有对应的盘点数，否则无法确定第一个月的期初库存。
- 净需求为负时置为 0 且不再展开下级件，以避免负库存倒推出错误的子件需求。

### PP-FLOW-002 计划结果审核与导出

- **目标**：对生成的生产计划进行多维度查询、验证、人工微调，并导出供下游采购、生产排程、能力规划等环节使用。
- **涉及角色**：生产计划员（R）、计划主管（A）、生产部长（C）、采购部（I）
- **前置条件**：生产计划已计算完成并保存
- **后置结果**：确认无误的计划版本被冻结并发布；计划数据导出至 Excel 或下游系统
- **标准流程**：
  1. **计划结果初步查看（生产计划员）**：查看统计信息，识别明显异常。
  2. **多维度过滤与查询**：按期间、完成品、自制件、工序、设备等维度过滤。
  3. **识别关键物料**：按"计划生产数 > 0"过滤，识别本期需生产物料，按数量排序找关键物料。
  4. **人工微调（生产计划员）**：特殊情况允许单条调整计划生产数，系统记录调整原因，标记"已调整"。
  5. **审核与冻结（计划主管）**：与生产、采购确认后冻结版本。
  6. **导出与发布（生产计划员）**：冻结版本导出 Excel，分发下游，系统标记"已发布"。
- **关键业务约束**：
  - 已冻结版本不允许直接修改，需重新计算并走审核流程。
  - 人工调整会影响期末库存递推，需补充调整说明。
