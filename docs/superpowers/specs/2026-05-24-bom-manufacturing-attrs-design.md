# BOM 制造部门与制造单元贯通设计

## 背景

当前 APS 的 BOM 主数据包含父子件、工序、设备、模腔数、制造周期、持台人数、单件节拍、报废率和版本号。用户需要在 BOM 中新增两个必填属性：

- 制造部门
- 制造单元

这两个属性不仅要在 BOM 主数据中维护，还要通过导入、查询、手工新增/编辑和计划计算链路一路传递到生产计划结果，并在后续相关页面中可见。

## 目标

本次变更实现以下目标：

1. BOM 表结构新增制造部门、制造单元两个必填字段。
2. BOM Excel 导入模板、导入解析和手工维护支持这两个字段。
3. 生产计划结果表持久化这两个字段，确保计算结果与当时 BOM 工艺属性一致。
4. 计划结果、人员需求、设备负荷等后续页面能看到这两个字段。
5. 不改变现有计划计算公式、人员需求公式和设备负荷公式。

## 方案选择

采用方案 A：

- 直接在 `t_bom` 和 `t_production_plan` 中增加字段；
- 计划计算时从 BOM 工艺行读取这两个属性并回填到 `ProductionPlan`；
- 不引入额外主数据字典表，不改变现有版本管理机制。

选择该方案的原因：

- 改动集中，链路清晰；
- 能保留历史计划结果的工艺快照，避免 BOM 后续修改影响历史结果解释；
- 与当前系统“以 BOM 为工艺主数据源”的设计一致。

## 数据设计

### BOM

在 `t_bom` 增加以下列：

- `manufacturing_department varchar(50) not null`
- `manufacturing_unit varchar(50) not null`

Java 实体 `Bom` 新增字段：

- `manufacturingDepartment`
- `manufacturingUnit`

二者均为必填字段。无论是 Excel 导入还是手工新增/编辑，都必须提供非空非空白值。

### 生产计划结果

在 `t_production_plan` 增加以下列：

- `manufacturing_department varchar(50) not null`
- `manufacturing_unit varchar(50) not null`

Java 实体 `ProductionPlan` 新增字段：

- `manufacturingDepartment`
- `manufacturingUnit`

这两个字段由计划计算时从 BOM 命中的工艺行回填，不由用户直接维护。

## Excel 模板与导入设计

### 模板列顺序

`template-bom.xlsx` 的 `BOM` Sheet 列顺序调整为：

1. 父零件
2. 子零件
3. 用量
4. 工序
5. 设备
6. 制造部门
7. 制造单元
8. 模腔数
9. 制造周期
10. 持台人数
11. 节拍
12. 报废率
13. 版本号

将两个新字段放在设备之后，保持工艺属性聚合在一起，便于业务维护。

### 导入规则

`ExcelImportService.parseBoms(...)` 增加以下规则：

- 父零件编码必须合法；
- 如果填写子零件，则子零件编码必须合法；
- 如果填写子零件，则用量必须大于 0；
- 制造部门必填；
- 制造单元必填；
- 报废率如填写，必须满足 `[0, 1)`；
- 版本号必填。

导入仍然保持“按版本号全删全导”的现有规则，不引入增量合并逻辑。

## 程序逻辑设计

### BOM CRUD

`/api/bom` 对应的新增、修改、查询返回值中增加以下字段：

- `manufacturingDepartment`
- `manufacturingUnit`

`BomService` 更新逻辑需要同步复制这两个字段。

### 计划计算

`PlanCalculationService` 当前会从命中的 BOM 工艺行读取：

- 工序
- 设备
- 模腔数
- 制造周期
- 持台人数
- 单件节拍
- 报废率

本次在同一逻辑块中追加读取：

- 制造部门
- 制造单元

并在写入 `ProductionPlan` 时与现有工艺字段一并保存。

### 后续报表

人员需求和设备负荷的公式保持不变：

- 人员需求继续基于 `planQty`、`staffCount` 等字段聚合；
- 设备负荷继续基于 `planQty`、`cycleTime`、`moldCavity` 等字段聚合。

本次只要求新字段可沿链路透传并展示，不改变现有统计口径。

## 页面设计

### BOM 管理页

`03-bom-list.html` 需要更新：

- 列表表格增加“制造部门”“制造单元”列；
- 新增/编辑弹窗增加两个必填输入框；
- 导入弹窗中的模板列说明改为新顺序；
- 本次不新增这两个字段的筛选项，避免无关扩张。

### 计划结果页

`08-plan-result.html` 需要更新：

- 列表增加“制造部门”“制造单元”列；

### 人员需求页

`10-workforce-report.html` 需要更新：

- 明细表或已有结果展示中增加“制造部门”“制造单元”列；
- 不改变当前聚合逻辑。

### 设备负荷页

`11-equipment-load.html` 需要更新：

- 结果展示中增加“制造部门”“制造单元”列或附加信息；
- 不改变当前聚合逻辑。

## 测试设计

按 TDD 顺序实施：

1. 为 BOM 导入增加失败与成功测试：
   - 缺少制造部门时导入失败；
   - 缺少制造单元时导入失败；
   - 正常行能正确解析并保存两个字段。
2. 为计划计算增加传递测试：
   - BOM 中设置制造部门、制造单元后，生成的 `ProductionPlan` 应带上相同字段。
3. 对 BOM CRUD 或服务层更新增加回归测试，避免新增字段在修改接口中漏写。

## 兼容性与迁移

- 由于新增字段为必填，数据库迁移时需要为已有演示数据同步补齐默认业务值或直接更新初始化 SQL；
- 所有示例数据、初始化脚本和模板文件都必须同步调整；
- 历史空字段数据不作为兼容目标，本次按“必须补齐”处理。

## 非目标

本次不包含以下内容：

- 制造部门/制造单元独立主数据字典；
- 下拉选项联动、编码表维护；
- 基于制造部门/制造单元的新筛选、新统计口径或新报表；
- 变更现有计划、人员、设备负荷计算公式。
